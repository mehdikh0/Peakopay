# مجوزها و اجرای مطمئن پس‌زمینه — اپ اندروید پیکو پی

این سند **هر مجوز درخواستی اپ** را مستند می‌کند: چرا لازم است، کجا درخواست می‌شود، و رفتار آن روی نسخه‌های مختلف اندروید. اصل: **حداقلِ دسترسی** — هیچ مجوز نامرتبطی (موقعیت، دوربین، میکروفون، مخاطبین، Accessibility، Device Admin) درخواست نمی‌شود و از هیچ API مخفی/غیررسمی استفاده نمی‌شود.

---

## ۱) ممیزی مجوزها — چه چیزی واقعاً لازم است؟

قابلیت واقعی اپ: دریافت پیامک واریز بانکی ← تجزیه ← ارسال امضاشده به سرور پیکو پی ← اعلان تأیید. برای این کار:

| مجوز | نوع | چرا لازم است |
|---|---|---|
| `RECEIVE_SMS` | خطرناک (runtime) | دریافت broadcast پیامک ورودی (`SMS_RECEIVED`) — تنها راه دریافت خودکار پیامک واریز بانکی. **پیش‌نیاز کل محصول است؛ بدون آن هیچ تراکنشی پردازش نمی‌شود.** |
| `POST_NOTIFICATIONS` | خطرناک (runtime از اندروید ۱۳) | اعلان «پرداخت تأیید شد» و اعلان وضعیت سرویس همیشه‌روشن |
| `INTERNET` | معمولی | ارتباط با سرور (OkHttp) |
| `ACCESS_NETWORK_STATE` | معمولی | WorkManager برای قید «فقط با اینترنت» و تشخیص بازگشت شبکه |
| `RECEIVE_BOOT_COMPLETED` | معمولی | پس از ری‌استارت گوشی، کارهای ارسال/ضربان و سرویس دوباره زمان‌بندی شوند |
| `FOREGROUND_SERVICE` + `FOREGROUND_SERVICE_SPECIAL_USE` | معمولی (اندروید ۱۴+ تایپ الزامی) | سرویس همیشه‌روشن اختیاری (نوع `specialUse` با توضیح subtype در منیفست) |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | معمولی | باز کردن دیالوگ **رسمی** اندروید برای معافیت از بهینه‌سازی باتری (فقط با کلیک کاربر) |
| `WAKE_LOCK` | معمولی (از WorkManager merge می‌شود) | نگه‌داشتن CPU حین ارسال صف در بازه‌های کوتاه |

### حذف‌شده‌ها (ممیزی)

- **`READ_SMS` حذف شد** (در نسخه‌های قبلی بود): خواندن broadcast با `RECEIVE_SMS` کافی است؛ صندوق پیامک هرگز خوانده نمی‌شود. اپ هیچ پیامکی را حذف یا تغییر نمی‌دهد.
- `SEND_SMS`، `CALL_LOG`، `CONTACTS`، `CAMERA`، `RECORD_AUDIO`، `ACCESS_FINE/COARSE_LOCATION`، `SYSTEM_ALERT_WINDOW`، `BIND_ACCESSIBILITY_SERVICE`، Device Admin: **هرگز درخواست نمی‌شوند** — هیچ قابلیتی از اپ به آن‌ها نیاز ندارد.

> نکته Google Play: مجوز SMS برای انتشار در Play محدودیت سیاستی دارد؛ پیکو پی به‌صورت APK مستقیم (sideload) توزیع می‌شود. اگر روزی انتشار Play خواستید، نیاز به درخواست استثنا یا تغییر معموری (default SMS handler) خواهد بود.

## ۲) جریان درخواست مجوز در زمان اجرا (Runtime)

هیچ مجوزی «کورکورانه» در لحظه اجرا خواسته نمی‌شود. الگوی واحد:

1. **توضیح قبل از درخواست** — در ویزارد راه‌اندازی (گام ۴ و ۵) و صفحه «وضعیت»، دلیل نیاز به هر مجوز به فارسی نوشته شده است.
2. **درخواست در لحظه مناسب** — مجوز پیامک بعد از همراه‌سازی موفق (وقتی کاربر می‌داند اپ قرار است چه کند)، مجوز اعلان هم‌زمان با آن.
3. **تشخیص رد شدن** — نتیجه دیالوگ دریافت و وضعیت ❌ با دکمه «فعال‌سازی» نمایش داده می‌شود.
4. **تشخیص رد قطعی («دیگر نپرس»)** — بعد از اولین رد + `shouldShowRequestPermissionRationale == false`، برچسب «رد شده — از تنظیمات» و دکمه **«باز کردن تنظیمات»** (عمق: تنظیمات اپ ← مجوزها) نمایش داده می‌شود.
5. **وضعیت لحظه‌ای** — صفحه «وضعیت پیکو پی» (آیکون چرخ‌دنده در داشبورد) همیشه وضعیت فعلی همه مجوزها را با ✓/✕ نشان می‌دهد.

| اندروید | تفاوت رفتار |
|---|---|
| 8–11 (API 26–30) | پیامک و اعلان بدون مجوز runtime اعلان؛ پیامک با دیالوگ |
| 12 (31) | PendingIntent ها باید IMMUTABLE باشند (رعایت شده)؛ سرویس FGS در پس‌زمینه محدود |
| 13 (33) | **اعلان runtime شد** — `POST_NOTIFICATIONS` درخواست می‌شود؛ بدون آن اعلان‌ها مخفی می‌شوند |
| 14 (34) | **FGS باید نوع داشته باشد** — پیکو پی `specialUse` + subtype اعلام‌شده؛ بوت‌ریسیور مجاز به شروع FGS (BOOT_COMPLETED جزو استثناهاست) |
| 15 (35) | محدودیت ساعات `dataSync` — چون نوع `specialUse` است شامل نمی‌شود؛ edge-to-edge پیش‌فرض (Compose رعایت می‌کند) |
| 16 (36) | targetSdk 35 باقی؛ بدون رفتار شکسته — سرویس/مجوزها مطابق مدل فعلی |

## ۳) سرویس همیشه‌روشن (Foreground Service)

- **چرا واقعاً لازم است:** مشتری در صفحه پرداخت منتظر تأیید است. سرویس فرایند را زنده نگه می‌دارد تا مسیر «پیامک ← تطبیق ← تأیید» در چند ثانیه تمام شود، حتی روی گوشی‌هایی که فرایندهای پس‌زمینه را به‌شدت می‌کشند (سامسونگ/شیائومی/…).
- **اختیاری است:** از صفحه «وضعیت» با یک سوییچ خاموش/روشن می‌شود. بدون آن هم اپ کار می‌کند: broadcast پیامک + WorkManager (تأییدها فقط ممکن است تا ۱۵ دقیقه تأخیر بیفتند).
- **اعلان سرویس:** کانال کم‌اهمیت (بدون صدا) `peakopay_service` با وضعیت لحظه‌ای: «متصل و فعال ✓» / «در انتظار تأیید مدیر…» / «قطع از سرور — تلاش مجدد…». ضربان داخلی هر ۹۰ ثانیه (در قطعی هر ۳۰ ثانیه).
- **نوع سرویس:** `specialUse` با `PROPERTY_SPECIAL_USE_FGS_SUBTYPE = "Merchant bank-SMS payment relay…"` (الزام اندروید ۱۴+).
- **آغاز مجدد خودکار:** `START_STICKY` + BootReceiver + شروع از داشبورد.
- **تکنیک‌های منسوخ استفاده نمی‌شود:** هیچ Alarm تکرارشونده‌ای برای زنده‌ماندن، هیچ `START_STICKY` صرفاً برای آپ‌تایم، هیچ Accessibility/Device Admin نیست.

## ۴) وابستگی‌های پس‌زمینه — مدل اجرا

| سازوکار | نقش |
|---|---|
| SMS BroadcastReceiver | سیستم حتی با اپ بسته broadcast را تحویل می‌دهد (ده ثانیه پنجره) → صف Room |
| WorkManager `upload_queue` | ارسال صف با قید اینترنت + backoff نمایی — پس از بازگشت شبکه خودکار ادامه می‌دهد |
| WorkManager `heartbeat` | ضربان/همگام‌سازی وضعیت هر ۱۵ دقیقه |
| Foreground Service (اختیاری) | پایداری بیشتر + وضعیت زنده |
| Room (outbox) | **ذخیرهسازی بادوام** — قطع برق/ری‌استارت چیزی از دست نمی‌رود |
| raw_hash یکتا | **جلوگیری از پردازش تکراری پیامک** (بازپخش broadcast) |
| Idempotency سمت سرور | جلوگیری از ثبت تکراری ارسال |

Doze/App Standby: در حالت عادی WorkManager با پنجره‌های نگهداری (maintenance windows) کار می‌کند؛ با معافیت باتری (پایین) + سرویس FGS عملاً همه‌جا به‌موقع اجرا می‌شود.

## ۵) بهینه‌سازی باتری

- تشخیص وضعیت فعلی: `PowerManager.isIgnoringBatteryOptimizations`
- دکمه «درخواست معافیت»: دیالوگ رسمی `ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` (فقط با تعامل کاربر — هیچ دور زدنی نیست)
- جایگزین: فهرست سیستمی `ACTION_IGNORE_BATTERY_OPTIMIZATION_SETTINGS`

### راهنمای گوشی‌های سامسونگ (One UI)

نام دقیق گزینه‌ها بین نسخه‌های One UI کمی متفاوت است؛ مسیرهای رایج:

1. **تنظیمات ← Battery ← Background usage limits**: اپ را از «Deep sleeping apps» خارج کنید و در **«Never sleeping apps»** اضافه کنید.
2. **تنظیمات ← Battery ← Battery optimization**: برای پیکو پی «Unrestricted/All» بگذارید (یا از داخل اپ: دکمه «درخواست معافیت»).
3. **تنظیمات ← Notifications ← App notifications**: روشن باشد (در اندروید ۱۳+ داخل اپ هم مجوز گرفته می‌شود).
4. **تنظیمات ← Apps ← پیکو پی ← Battery → Unrestricted** و «Allow background activity» (در برخی مدل‌ها).
5. اگر اعلان تأیید نمی‌آید: حالت «Do not disturb» و «Focus mode» را چک کنید.

اپ دکمه «باز کردن صفحه مربوطه (در صورت امکان)» دارد که برای سامسونگ/شیائومی/هواوی/OPPO میانبر سازنده را می‌آزماید و اگر نبود، به فهرست عمومی باتری می‌رود.

### سایر سازنده‌ها

- **شیائومی/Redmi/Poco:** Battery ← «No restrictions» + Security Center ← Autostart
- **هواوی:** Battery ← App launch ← دستی + Run in background
- **OPPO/Realme:** Battery ← «Allow background activity» + «Allow auto-start»

## ۶) ویزارد راه‌اندازی ۱۰ گامی

بعد از نصب، اولین اجرا ویزارد را نشان می‌دهد (با امکان «رد کردن»):

| گام | محتوا |
|---|---|
| ۱ | خوش‌آمد + توضیح نقش اپ |
| ۲ | آدرس سرور (آماده‌سازی) |
| ۳ | همراه‌سازی با کد کوتاه (فرم واقعی همراه‌سازی داخل گام) |
| ۴ | مجوز پیامک: دلیل + درخواست + مدیریت رد/رد قطعی |
| ۵ | مجوز اعلان‌ها (اندروید ۱۳+) |
| ۶ | سرویس پس‌زمینه: توضیح + سوییچ روشن/خاموش |
| ۷ | باتری: معافیت رسمی + راهنمای سامسونگ/سازنده‌ها |
| ۸ | تست دریافت پیامک: اجرای تجزیه‌گر روی پیامک نمونه (محلی، بدون ارسال) |
| ۹ | تست اتصال واقعی به سرور (DNS/TLS/health) |
| ۱۰ | جمع‌بندی سلامت: ۴ چک سبز/قرمز + پایان |

## ۷) صفحه «وضعیت پیکو پی» (داشبورد مجوزها)

از داشبورد (آیکون چرخ‌دنده) در دسترس است: دریافت پیامک / اعلان‌ها / بهینه‌سازی باتری / سرویس همیشه‌روشن (سوییچ) / اتصال به سرور (بررسی زنده با پیام علت) / راهنمای سازنده‌ها / باز کردن تنظیمات اندروید اپ + «آخرین پیامک بانکی دریافت‌شده».

## ۸) صفحه عیب‌یابی (Diagnostics)

از داشبورد (آیکون i): نسخه اندروید، سازنده/مدل، نسخه اپ، آدرس سرور، وضعیت تأیید دستگاه، مجوز پیامک/اعلان، وضعیت سرویس، وضعیت باتری، آخرین پیامک دریافت‌شده، آخرین همگام‌سازی موفق، آخرین خطای همگام‌سازی. **هیچ کلید/راز یا اطلاعات بانکی نمایش داده نمی‌شود** — برای پشتیبانی کافی است کاربر اسکرین‌شات بگیرد.

## ۹) ریکاوری و پایداری

- کشته‌شدن سرویس: `START_STICKY` + شروع مجدد از داشبورد/بوت.
- کشته‌شدن فرایند: وضعیت در Room/Prefs بادوام است؛ broadcast بعدی همه‌چیز را ادامه می‌دهد.
- قطع اینترنت: صف Room + قید شبکه WorkManager؛ اتصال که برگردد خودکار ارسال می‌شود.
- ری‌استارت گوشی: BootReceiver کارها و سرویس را دوباره می‌چیند (BOOT_COMPLETED مجاز به شروع FGS است).
- تکراری‌ها: raw_hash در اپ + Idempotency-Key در سرور.
