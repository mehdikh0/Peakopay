# نصب پیکو پی روی cPanel/LiteSpeed — راهنمای دقیق

این راهنما برای همین پروژه، با همین فایل‌ها و بدون SSH نوشته شده است. فقط cPanel File Manager، MySQL Database Wizard و Cron Jobs استفاده می‌شود — نه Composer، نه ترمینال، نه ویرایش کد.

**مثال همین راهنما:**

| مورد | مقدار |
|---|---|
| دامنه | `pay.peakora.ir` |
| Document Root | `/home/ixddoaao/public_html/pay` |
| PHP | 8.2 (LiteSpeed) |
| دیتابیس | MySQL/MariaDB |

---

## معماری نصب (یک قاعده واحد)

**Document Root باید همان پوشه‌ای باشد که محتوای ZIP را در آن باز کرده‌اید.** یعنی:

```
/home/ixddoaao/public_html/pay/     ← Document Root = همین پوشه
├── .htaccess          ← همه مسیریابی و امنیت اینجا (فقط همین یک فایل!)
├── index.php          ← Front controller (همه درخواست‌ها از این می‌گذرند)
├── cron.php           ← نگهداری دوره‌ای (اختیاری)
├── .env.example       ← نمونه تنظیمات محیطی (اختیاری — نیازی به آن ندارید)
├── app/               ← کد برنامه        ← از وب مسدود (403)
├── config/            ← کانفیگ + قواعد پیامک ← از وب مسدود (403)
├── migrations/        ← SQL مهاجرت‌ها     ← از وب مسدود (403)
├── storage/           ← لاگ/کش            ← از وب مسدود (403)
├── docs/              ← همین راهنماها     ← از وب مسدود (403)
└── assets/            ← CSS/JS/فونت/آیکون ← عمومی (این‌ها سرو می‌شوند)
```

> ⚠️ پوشه `public/` در نسخه‌های قدیمی وجود داشت. **حذف شد.** اگر نسخه قدیمی را آپلود کرده‌اید، پوشه `public_html/pay` را کامل خالی کنید و از ZIP جدید شروع کنید. `public_html/pay/public` **اشتباه** است.

مسیرهای مجاز وب: `/` ، `/install` ، `/admin` ، `/pay/{token}` ، `/api/v1/...` ، `/health` ، `/assets/...` ، `/cron.php?token=...`

## گام ۰ — ساخت دامنه و DNS

1. cPanel ← **Domains** ← Create a New Domain (یا Subdomains برای ساب‌دامین):
   - Domain: `pay.peakora.ir`
   - Document Root: `public_html/pay` (دقیقاً همین — نه `public_html/pay/public`)
2. DNS: رکورد A ساب‌دامین `pay` به IP سرور (اگر دامنه روی همین هاست است، خودکار ساخته می‌شود). تا resolved شدن صبر کنید:
   `ping pay.peakora.ir` باید IP سرور را نشان دهد.

## گام ۱ — SSL (الزامی قبل از نصب)

cPanel ← **SSL/TLS Status** ← دامنه `pay.peakora.ir` را تیک بزنید ← **Run AutoSSL**.
چند دقیقه صبر کنید و مطمئن شوید `https://pay.peakora.ir` بدون خطای گواهی باز می‌شود.

## گام ۲ — PHP 8.2 و افزونه‌ها

cPanel ← **MultiPHP Manager** (یا Select PHP Version در هاست‌های lsapi):

- نسخه PHP را برای `pay.peakora.ir` روی **8.2** (یا بالاتر) بگذارید.
- در **Select PHP Version ← Extensions** این‌ها روشن باشند:

| افزونه | وضعیت |
|---|---|
| `pdo_mysql` | الزامی |
| `openssl` | الزامی |
| `mbstring` | الزامی |
| `curl` | الزامی |
| `json` | الزامی (همیشه هست) |
| `session` | الزامی (همیشه هست) |
| `filter` | الزامی (همیشه هست) |
| `sodium` | **اختیاری** — نبودش مانع نصب نیست؛ پیکو پی خودکار با AES-256-GCM (OpenSSL) کار می‌کند |

> اگر `mbstring` خاموش باشد، نصب‌کننده در گام ۱ نصب خطای واضح نشان می‌دهد (نه صفحه سفید) و راه‌حل را می‌گوید.

## گام ۳ — ساخت دیتابیس (بدون SQL دستی)

cPanel ← **MySQL® Database Wizard**:

1. New Database: `peakopay` → نام کامل می‌شود مثلاً `ixddoaao_peakopay`
2. Username + رمز قوی بسازید (Generate Password) و **بنویسید**:
   - نام دیتابیس: `ixddoaao_peakopay`
   - نام کاربری: `ixddoaao_peakopay`
   - رمز
3. User Added ← همه تیک‌ها (**ALL PRIVILEGES**) ← Next Step.

هیچ جدولی نسازید — نصب‌کننده همه را خودش می‌سازد.

## گام ۴ — آپلود و Extract

1. فایل `peakopay-cpanel.zip` را دانلود کنید.
2. cPanel ← **File Manager** ← وارد `public_html/pay` شوید (اگر نبود بسازید).
3. دکمه **Upload** ← فایل ZIP را آپلود کنید.
4. در File Manager روی `peakopay-cpanel.zip` راست‌کلیک ← **Extract** ← Extract در همین پوشه (`/home/ixddoaao/public_html/pay`).
5. ZIP را بعد از Extract پاک کنید.
6. بررسی نهایی: باید `index.php` و `.htaccess` مستقیماً داخل `public_html/pay` باشند (نه یک پوشه بالاتر/پایین‌تر).

### دسترسی‌ها (Permissions)

در اکثر هاست‌ها نیازی به تغییر نیست. اگر نصب‌کننده گام ۱ گفت «قابل نوشتن نیست»:

| مسیر | دسترسی |
|---|---|
| `storage/` و زیرپوشه‌هایش (`logs`, `cache`, `sessions`) | 755 (یا 775) |
| `config/` | 755 (یا 775 فقط تا پایان نصب) |

> نکته File Manager: تیک **Settings ← Show Hidden Files (dotfiles)** را بزنید تا `.htaccess` و `.env.example` را ببینید.

## گام ۵ — نصب وب (نصب‌کننده ۷ گامی)

در مرورگر باز کنید:

<div dir="ltr">

```
https://pay.peakora.ir/install
```

</div>

**این آدرس چطور کار می‌کند؟** درخواست `/install` توسط `.htaccess` به `index.php` (front controller) می‌رود و از آنجا به `InstallController` — فایل جداگانه‌ای به نام `install.php` وجود ندارد؛ همه‌چیز از همان `index.php` مسیریابی می‌شود.

| گام | چه کاری | نکته |
|---|---|---|
| ۱ | بررسی محیط (PHP، افزونه‌ها، دسترسی نوشتن، HTTPS) | همه الزامی‌ها باید سبز باشند؛ Sodium اختیاری است |
| ۲ | دیتابیس | Host=`localhost` + نام/کاربر/رمز گام ۳ ← «تست اتصال و ساخت جدول‌ها» — ۱۵ جدول خودکار ساخته می‌شود |
| ۳ | حساب مدیر | ایمیل + رمز قوی (برای ورود به پنل) |
| ۴ | تنظیمات فروشگاه | نام، واحد نمایش (تومان/ریال)، منطقه زمانی |
| ۵ | کارت مقصد | شماره کارت واریز + بانک + صاحب کارت (رمزنگاری‌شده ذخیره می‌شود؛ نمایش همیشه ماسک) |
| ۶ | اتصال ووکامرس | آدرس فروشگاه + نمایش **یک‌باره** سه کلید `st_` / `hpk_` / `whsec_` — همان‌جا ذخیره‌شان کنید |
| ۷ | پایان | فایل قفل `storage/installed.lock` ساخته می‌شود و نصب‌کننده برای همیشه قفل می‌شود |

بعد از نصب، ورود پنل: `https://pay.peakora.ir/admin`

### فایل `.env` (اختیاری — معمولاً لازم نیست)

نصب‌کننده همه تنظیمات را می‌پرسد و در `config/config.php` (از وب مسدود) ذخیره می‌کند؛ **هیچ فایلی را دستی ویرایش نمی‌کنید.**

اگر خواستید از قبل مقادیر آماده باشند (مثلاً برای پرشدن خودکار فرم دیتابیس)، فایل `.env.example` را به `.env` تغییر نام دهید و مقدارها را پر کنید:

```env
APP_ENV=production
APP_URL=https://pay.peakora.ir
#DB_DSN=mysql:host=localhost;port=3306;dbname=ixddoaao_peakopay;charset=utf8mb4
#DB_USER=ixddoaao_peakopay
#DB_PASSWORD=رمز-دیتابیس
SESSION_SECURE=true
WEBHOOK_ALLOWED_HOSTS=
```

اولویت: `config/config.php` (خروجی نصب‌کننده) برای داده‌های نصب معتبر است؛ `.env` فقط برای `SESSION_SECURE` و `WEBHOOK_ALLOWED_HOSTS` و `APP_ENV` همیشه اولویت دارد. فایل `.env` از وب 403 می‌شود.

## گام ۶ — کران نگهداری (اختیاری ولی توصیه‌شده)

> **مهم:** تطبیق و تأیید پرداخت‌ها هرگز به کران وابسته نیست — همان لحظه انجام می‌شود. کران فقط انقضای پرداخت‌های سرآمده و پاک‌سازی داده‌های قدیمی است.

cPanel ← **Cron Jobs** ← Add New Cron Job:

- Common Settings: **Every 15 minutes** (`*/15 * * * *`)
- Command:

<div dir="ltr">

```
php -q /home/ixddoaao/public_html/pay/cron.php
```

</div>

اگر هاست اجازه cron نمی‌داد، جایگزین HTTP: پنل پیکو پی ← تنظیمات ← پیشرفته ← آدرس HTTP کران (با توکن اختصاصی) را بردارید و در یک سرویس کران آنلاین (مثل cron-job.org) با فاصله ۱۵ دقیقه بگذارید.

## گام ۷ — اتصال ووکامرس

۱. در وردپرس: افزونه‌ها ← افزودن ← بارگذاری ← `peakopay-woocommerce.zip` ← نصب و فعال.
۲. ووکامرس ← تنظیمات ← پرداخت‌ها ← **پیکو پی (کارت به کارت)** ← فعال/مدیریت.
۳. مقادیر (از گام ۶ نصب پیکو پی):

| فیلد | مقدار |
|---|---|
| آدرس سرور پیکو پی | `https://pay.peakora.ir` |
| شناسه فروشگاه | `st_…` |
| کلید API | `hpk_…` |
| کلید امضای وب‌هوک | `whsec_…` |
| واحد مبالغ فروشگاه | تومان (اگر قیمت‌ها تومان‌اند) |

۴. دکمه **«تست اتصال به پیکو پی»** ← باید ✅ بدهد ← ذخیره.
۵. تست سمت سرور: پنل پیکو پی ← تنظیمات ← اتصال ووکامرس ← «تست اتصال».

## گام ۸ — اپ اندروید

۱. پنل ← **دستگاه‌های همراه** ← «ساخت کد همراه‌سازی» (کد ۸ حرفی، ۱۰ دقیقه اعتبار).
۲. اپ را نصب کنید — APK آماده: `Peakopay-Android-v2.3.1.apk` از صفحهٔ Releases یا بستهٔ تحویل (برای بازسازی از سورس: `android/README.md`).
۳. در اپ: آدرس سرور `https://pay.peakora.ir` + کد + نام دستگاه ← همراه‌سازی.
۴. در پنل، دستگاه را **تأیید** کنید؛ اپ «متصل و فعال» می‌شود و مجوز پیامک می‌گیرد.

## گام ۹ — اولین تست و فعال‌سازی نهایی

1. پنل ← تنظیمات ← پیشرفته ← **حالت تست = روشن**.
2. پنل ← ابزارهای تست ← «ساخت پرداخت تستی» (حداقل ۲٬۰۰۰ تومان) ← «شبیه‌سازی پیامک بانکی».
3. نتیجه را در گزارش‌ها ببینید (برچسب «تست»؛ سفارش واقعی ووکامرس تغییر نمی‌کند).
4. حالت تست را **خاموش** کنید.
5. یک سفارش واقعی کوچک بزنید و سه چیز را چک کنید: اعلان اپ، تکمیل سفارش ووکامرس، «پرداخت شد ✅» روی صفحه پرداخت.
6. cPanel ← Backup ← بکاپ کامل.

## رفع اشکال

### HTTP 500 موقع `/install` — چک‌لیست دقیق

1. **ساختار پوشه‌ها:** `index.php` باید مستقیماً در `public_html/pay` باشد، نه در `public_html/pay/backend` و نه در `public_html/pay/public`. اگر تودرتو است: محتوا را یک سطح بالا بیاورید (یا پاک کنید و Extract را دوباره درست انجام دهید).
2. **نسخه PHP:** MultiPHP Manager ← 8.1 یا بالاتر (8.2 توصیه). نسخه‌های 7.x پروژه را اجرا نمی‌کنند.
3. **افزونه‌های الزامی:** Select PHP Version ← `pdo_mysql`, `openssl`, `mbstring`, `curl` روشن باشند.
4. **`.htaccess` آپلود شده؟** فایل‌های نقطه‌دار در File Manager مخفی‌اند: Settings ← Show Hidden Files. اگر نبود، از ZIP جداگانه آپلودش کنید.
5. **لاگ واقعی خطا:** `storage/logs/errors-YYYYMMDD.log` و `php-errors.log` را در File Manager باز کنید — پیام دقیق همان‌جاست. (نسخه فعلی پیکو پی صفحه خطای 500 را با «کد پیگیری HP-…» نشان می‌دهد و مسیر لاگ را روی همان صفحه می‌نویسد؛ این متن برای نسخه‌های قبلی/موارد پیش از بوت است.)
6. اگر صفحه سفید باقی ماند: cPanel ← **Errors** (لاگ PHP هاست) را ببینید — احتمالاً PHP 7.x فعال است یا افزونه‌ای خاموش است.

### بعد از نصب

| نشانه | راه‌حل |
|---|---|
| «اتصال به دیتابیس ناموفق» | نام/کاربر/رمز دقیق cPanel (با پیشوند `ixddoaao_`)، Host=localhost، ALL PRIVILEGES |
| «پوشه config/storage قابل نوشتن نیست» | دسترسی 755/775 طبق گام ۴ |
| سفارش ووکامرس تکمیل نشد | پنل ← پرداخت‌ها ← جزئیات ← «ارسال مجدد وب‌هوک»؛ تست وب‌هوک در تنظیمات ← اتصال ووکامرس |
| پیامک اپ ارسال نشد | مجوز پیامک + بهینه‌سازی باتری خاموش + وضعیت دستگاه «فعال» |
| «کد پیگیری HP-…» روی صفحه کاربر | پنل ← گزارش‌ها ← لاگ‌ها؛ همان کد را جستجو کنید |

### محل لاگ‌ها

| فایل | محتوا |
|---|---|
| `storage/logs/errors-YYYYMMDD.log` | خطاهای برنامه (با کد پیگیری HP-…) |
| `storage/logs/app-YYYYMMDD.log` | رخدادهای عادی (ساخت پرداخت، وب‌هوک، …) |
| `storage/logs/php-errors.log` | هشدارهای PHP |
| لاگ افزونه ووکامرس | ووکامرس ← Status ← Logs ← `peakopay-…` (اگر «لاگ دیباگ» روشن باشد) |

### انتقال هاست / بکاپ

- بکاپ: cPanel ← Backup (دیتابیس + پوشه `pay`).
- انتقال: در هاست جدید دیتابیس بسازید، ZIP را Extract کنید، دیتابیس قدیمی را import کنید و پوشه را کپی کنید؛ `config/config.php` خودش کار می‌کند (اگر رمز دیتابیس فرق دارد، از پنل ← تنظیمات ← سیستم ← «بازنشانی نصب» استفاده کنید یا فایل config را با ویرایشگر File Manager اصلاح کنید — تنها موردی که دست می‌زنید).
